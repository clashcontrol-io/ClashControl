## Known Issues & Gotchas

Keep every entry unless it's truly obsolete. Add a note when something gets fixed.

### Rendering / viewer
- **Three.js r180 API**: use r180 docs. It loads as ESM via the import map. The post-r155 color-management and light-intensity tuning is deliberate (e.g. rendered-mode exposure 0.4), so don't reset it to library defaults.
- **View cube** must use `cubeGroup.quaternion.copy(camera.quaternion).invert()`. The camera-position approach mirrors the view.
- **`invalidate()`** is required after any visual change. `_needsRender` > 0 means render, and it decrements per frame. The culling pass (`updateCulling`) throttles to 1 per 8 frames, so a model-visibility change needs `S._forceCull`; a bare `invalidate()` isn't enough.
- **Ghost material is shared** (`MeshBasicMaterial 0x334155, opacity .08`), so never dispose it per mesh. The shared #572 phong cache is also never disposed per mesh; only the per-mesh `_styleMats`/`_edges` are disposed on unload.
- **BatchedMesh traps:**
  - Any scene material/clipping sweep written before batching probably filters on `expressId==null && !isInstancedMesh`, which silently skips batches. Include `userData._isCCBatch`. The render-style swap on batches has not been audited (cosmetic).
  - Off-scene original meshes have no parent, so their `matrixWorld` is a stale identity. Refresh it from `.matrix`, as the outline/bbox code does.
- **Chunk-merge history** (don't repeat it): hand-rolled mesh merging broke identity features, and ~49 setters never became chunk-aware. It went through several enable/revert cycles and was removed in `704837f`. It was replaced by native BatchedMesh with off-scene per-element proxies (`element.meshes[]` stays the source of truth), plus CI regression gates in `tests/browser/smoke.mjs`.
  - "Free RAM"/dehydrate was reverted the same day. Park is the properly scoped redo of that idea.
  - `_instKey` must use `geometryExpressID`, never a derived hash. Scale-invariant hashes grouped 12 m and 18 m piles together ("spiky model").
  - Retire legacy fallback paths in the same change as the fix; don't leave zombie code behind.
- **Removing the proxy pattern was REJECTED** ("BatchedMesh as sole render source", large-model plan Phase 3). It reintroduces the chunk-merge failure class. If memory must come down, target the already-batched subset narrowly.
- **PostFX (SAO/Outline/SMAA)** is the highest-risk area. Re-enable only as an opt-in, without SMAA, and verify on batched models before any default flip.
- **Present-mode click-to-frame is intentionally disabled** ("read-only walkthrough"). Don't "fix" it.
- **Orbit/zoom:** `makeOrbit` is a top-level helper and cannot see App's `modelsRef`/`_elemsBBox` (that threw and broke zoom). Get bounds via `window._ccViewport.getBounds()`. Every selection path recentres the pivot via `_highlightById` (`keepPivot` opts out).
- **Occluder hide** must use each mesh type's native hide:
  - Mesh: `.visible`
  - InstancedMesh: `setMatrixAt(_INST_HIDE_MX)`
  - BatchedMesh: `setVisibleAt`

  `_ccTempHide` has no InstancedMesh branch. Never call `ghostOthers`/`unghostAll` from occluder code.
- **Section planes follow the building grid.** Axis sections (X/Y/Z), their outline, cut lines, drag gizmo and the whole-model section box use `_ccPlanFrame()` (dominant wall direction via `_ccSectionClipping.dominantPlanAngle`, cached per model set). Angle 0 (world-aligned or no clear grid) is exactly the old world-axis behaviour. Don't reintroduce `box.min[axis]`-style world-axis math for sections — go through `frame.cut(axis,pos)` / `frame.posOf` (`tests/browser/section-plane-alignment.mjs`).
- **Clipping:** the core turns `renderer.localClippingEnabled` off when no section is active. `tiles.js` site-clearing re-asserts it each frame.
- **North/georef sign:** the applied rotation was negated after a live test. If a model rotates the wrong way, suspect a per-authoring-tool sign difference and add a flip toggle. Georef is context/QA only; the clash engine uses local coordinates.
- **3D Tiles ENU→Y-up sign** is unverified with Google tiles. If the city is mirrored or under the model, flip the rotX sign.
- **Z-index:** use the scale in DESIGN.md §Layers (`--z-panel` 100 … `--z-tooltip` 5000). `.cc-desktop-topbar`/`.cc-top-toolbar` are their own stacking contexts on the dropdown tier — a menu nested in them can't rise above that tier.
- **Measuring overlap:** `getBoundingClientRect` reports unclipped geometry for children under `overflow:hidden`. Confirm "overlap" with a screenshot.

- **Element → mesh lookups go through the per-model mesh index** (`_ccMeshesByEid(S.mg, eid)` / `S._findMeshByRef`, INTERNALS §21.54): never `S.mg.traverse` to find an element's meshes. Batch visibility goes through `_ccBatchApplySlot`; pass the changed expressIds to `_ccBatchApplyVisibility(root, eids)`. Scene effects key on `meshKey` / `visKey` (Viewer), not on `s.models` identity — a new effect that reads model meshes or visibility should do the same. `_ccPlanFrame` and other caches inside `Viewer` must live on `state3d` (Viewer re-creates its local vars every render).
- **Scene picks go through `S.scenePick`** (`viewer-pick-index.js`, INTERNALS §21.47): never call `raycaster.intersectObjects(S.mg.children, true)` in new code — use `S.scenePick.first(rc, [pred])` / `.firstVisible` / `.all`. The index follows the scene graph by itself (model groups, container child add/remove, instance/batch matrix versions, container/root matrices); code that moves baked geometry in place another way must call `S.scenePick.invalidate()`. `S.scenePick.bruteForce = true` is the test-only full-raycast path.

- **Rooms (IfcSpace)** — web-ifc's `StreamAllMeshes` never yields IfcSpace; both loaders stream them in a second `StreamMeshes(spaceIds)` pass. Room meshes are marked by `_ccMarkSpaceMesh` (shared translucent material, no depth write, no `_instKey`) and live on Three.js layer 3 (`_CC_SPACE_LAYER`), which the camera renders only while `prefs.showSpaces`; layer 4 force-shows a selected room. Every default raycaster (layer 0) ignores rooms for free — don't move them to layer 0. Keep them out of new bounds/material sweeps via `userData._ccSpace` / `_ccIsSpaceEl`. Geo caches without `sp:1` cold-parse once (`_ccGeoCacheLacksSpaces`).

### Clash review / triage (2026-10-23)
- **Bucket precedence** (first match): handled > contact > provided > provision (provision group 'classify') > zone (any other classify group) > duplicate-type stays review > twice > embedded > finish > graze > adjacent (soft, both roles arch/struct/finish, gap > 30 % of required) > review. Planted cases: crossings/contained/clearance stay review (incl. P15 plate through covering and P20 column vs its architect copy — a covering vs a column is NOT 'finish'; only finish+finish or movable furniture is).
- **Extent needs bboxA/bboxB sizes + depth**; local-engine clashes stamp sizes but stay 'unknown' (AABB depth). Graze = depth < min(25 mm, 10 % of the thinner element); through = depth ≥ the smaller cross-section of passer/host (passer = smaller middle dimension).
- **`_ccTriageModel(s)` / `_ccReviewModel(s)`** are module-level memos keyed on state identities (clashes/rules/models[/filters/facets]) shared by list, overview, BCF and report — don't recompute buckets per component.
- **Overview UI:** opened explicitly (`triage.view==='overview'`) it stays open with an empty state when facets/buckets leave nothing; the facets live in a `compact` TriageFilterBar popover there and the sidebar hides its own copy (`!_ccOverviewVisible`). Snapshots: IntersectionObserver requests visible cards `front:true` and `cancel()`s cards that leave; `failed(c)` = no geometry (never retried); each card subscribes to `cc-snapshot` for its own key; slice budget 60 ms while the overview is mounted.
- **Overview** is `.cc-overview` absolutely positioned between the floating panels (insets measured from `.cc-left-panel`/`.cc-ai-panel`), fixed sheet on phones. It opens automatically only after INTERACTIVE runs (`triage.autoOpen`, set by `_ccRunDetectionInteractive`) and ≤ 150 review items, so automation/tests never get an overlay over the canvas.
- **BATCH_UPD_CLASH with `ids`** targets those clashes (selection untouched); changelog/sync/training resolve the set through `_ccBatchIdSet`; undo via `CLASH_BATCH_RESTORE`.
- Snapshot rendering draws ONLY the pair + the elements whose box meets the local section box (≤ 300 elements / 400k triangles, nearest first) into a 320×200 MSAA target — never the live scene (a whole-scene context pass cost 1–3.5 s per card on a 20k-clash federation). SwiftShader: ~140–190 ms median per card, most of it the readback sync; one card per idle slice there. `stats().lastPhases` has the split.

### React / htm / UI
- **Clash objects are immutable state — never mutate one in place after it is in `s.clashes`.** The list/triage/autosave caches are WeakMaps keyed by clash object identity (INTERNALS §21.45); an in-place edit would show and save stale data. A small action must cost what it changes: `tests/browser/action-cost.mjs` asserts render counts (`?ccRenderCount=1` → `window.__ccRenderCount`).
- **Rules of Hooks:** never call hooks inside `${cond && function(){...}()}` render IIFEs. That crashed clash review (React #310). Extract a component instead (e.g. `ClashToleranceEditor`). Prefer native `<details>` for disclosure, since it needs no state.
- **htm `<img src=${…}>` must be written `\x3Cimg`.** In plain report strings, split it as `'<im'+'g'`. Otherwise Chromium's preload scanner fetches the literal `${…}` URL (404 noise). The cooked string is identical for the htm parser.
- **Lazily-loaded addon state slices** (`s.smartBridge`, `s.openaecBridge`) exist only after first activation, so every core read must be null-guarded. Addon `reducerCases` only run while the addon is active: call `_ccActivateAddon(id)` before dispatching (e.g. the string action `'REVIT_BRIDGE'`; `A.REVIT_BRIDGE` doesn't exist). Lazy activation must fire `def.onEnable` after it resolves.
- **Detection can run from non-interactive triggers** (NL/AI, auto-run). Use `window._ccToast`, never `confirm()`, inside detection.
- **i18n:**
  - `_cc_t(key, english, vars)` falls back to English and has no plural rules (use separate keys).
  - Do NOT translate:
    - IFC/Revit pset/property names (they are lookup keys)
    - the NL regex parser and its suggestion chips (they are fed back into the English parser)
    - command-palette `keywords`
    - the GitHub issue body in `MemoryWarningModal`
    - product names and format IDs (BCF/PDF/DXF, PDOK)
    - ViewCube canvas labels
  - Wiring tests anchor on literal source text, so update them when you wrap a string.
- **Addon guard:** core calls into addons use `typeof window._ccFoo === 'function'`. The WASM addon publishes its globals only after init succeeds, because the core treats their existence as "skip the JS fallback" and a stub would silently report 0 clashes.
- **Before designing a new report/export**, grep for `window.print`, `@media print` and `⎙`. `_ccClashReport`, `_ccDataQualityReport` and `generateValidationReport` already exist.

### Clash semantics
- **Merged rows are hub × partners** (2026-10-23): a clash joins a row only through the row's OWN hub element (same partner type, ≤ 250 mm, same type); `_groupHub` names the hub side, `_groupedElems` / `_groupedDist` the partners and their own distances. Code reading merged rows expands (hub, partner) — never A × grouped AND grouped × B. Mesh `closed` (`_ccMeshTopo`) means mod-2 closed (parity defined), not edge-manifold.
- **Coplanar triangle pairs are deliberately NOT kernel hits** (JS `_triTriTest`, Rust `tri_tri_test`, Python `tri_tri_intersect`) — explicit policy, kept. Flush contact is everywhere. Duplicates / coincident same-side faces are still found: by the hit refinement's coplanar same-orientation rule, not the kernel.
- **Kernel degenerate cases (fixed 2026-10-22, JS + Rust identically):** Möller's lone-vertex choice now handles zero distances (an edge lying in the other plane used to give r=0/0 → NaN "hits": separated elements at distance 0, NaN points filling the 8-point collect cap so a real crossing was dropped), plane distances within 1 µm snap to 0 (a same-sign near-zero vertex used to EXTRAPOLATE the interval: a 25 mm gap read as a hit), degenerate-triangle threshold is |n|² < 1e-24 (was 1e-10, which skipped every triangle under ~5 mm²), and a NaN result never counts as a hit. The wasm self-checks include these cases, so a stale binary is never published.
- **Hit refinement = JS post-step after the kernel** (`_ccResolvePair` / `_ccTouchVerdict` / `_ccContainment` / `_estimatePenetrationDepthM`, index.html): identical on every path by construction (kernel answers stay bit-identical). A kernel hit is a crossing only if some triangle pair crosses transversally by more than the **contact tolerance tau = 0.1 mm + 4.8e-7·|coord|** on both triangles (or coplanar same-side overlap wider than tau, or a vertex > tau inside the other closed mesh); otherwise it is a **`type:'contact'`** clash (distance 0, severity info, BCF TopicType "Contact"), hidden by default behind a count + one-click show (`rules.hideContacts`, `filters.showContacts`, like provided openings), never also a 0 mm soft clash. Gaps below 0.1 mm are contacts too. **Hard-only runs report crossings only** (no distances are computed there, so no contacts). Nested closed solids are hard (`_ccContainment`, closed = edge-manifold, cached per element in `el._topo`; open containers have no inside). The in-kernel min-distance containment fix was removed (it ran on open meshes).

- **Discipline/role classification (2026-10-22):** `el._ccCls` (interned, frozen: `d, sub, src, stated, ev, role, roleSrc, roleEv, dm`) is stamped by `_ccClassifyLoadedResult` on EVERY model-creation path (IFC, GLB+IFC, sidecar, project restore, unpark). `dm` = top-level discipline came from the model, so `elementDiscipline`/`elementMatrixKey` follow the live `model.discipline` (a user re-label wins). - **Large-model performance:**
  - Measure with `stats.phases`/`stats.sceneSub` (including `transferGap`) read off the loaded model, not by parsing `console.table`.
  - The old "174s / 145k elements" figure was a fixture-generator bug (bare `IfcCartesianPoint` as profile Position); don't cite it.

- **Progressive loading = a DISPLAY-ONLY preview (2026-10-23, flag `progressivePreview`, default on).** Partial *models* are still not built, deliberately: `model.elements/meshes` only ever hold the complete committed model. With `stream:true` the worker transfers geometry buffers in ordered `'geo'` batches while `StreamAllMeshes` runs (postMessage from inside the callback is fine — no yield needed); the final `'result'` carries none, and `loadIFCWorker` decodes from the SAME typed arrays, so the model is identical by construction. `_ccLoadPreview` draws merged world-space chunks into a group directly under the scene (not `S.mg`, raycast no-op, never in state/cache/export), paces frames on `S._lastRenderMs` and stops growing above 400 ms/frame (a software rasteriser otherwise delays the commit), and is torn down by the `[s.models]` effect once the committed group is in (`modelShown`), else after 2 s; cancel/crash/fallback drop it at once. - **Parallel file loading (`parallelLoad`, default on):** processFiles turns each .ifc into a job; `_ccIfcLoadPlan()` = ≤3 parses at once (2 on ≤4 GB, 1 on ≤2 GB or main heap > 60 %), memory budget `deviceMemory × 0.5`, cost `size × 8 + 64 MB` (measured: WASM heap ≈ 2× file size). Jobs start strictly in file order; COMMITS stay in the chain in file order (ids/order/colours deterministic). A cancel stops the whole batch (sequential mode keeps the old per-file behaviour). Props can land before a job's commit — held and merged then; the lazy gate is released exactly once on every path.
- **`_mergeLazyProps(modelId, propMap, elementsHint)`:** the hint (the committed result's elements) always wins. Without it, psets of small files (props within a frame of ADD_MODEL) were never merged into the live model, and on a same-id REPLACE they went into the OLD version's elements (both pre-existing races, found by the new digest checks).
- **Sharded single-file load (2026-10-23, flag `shardedLoad`, default on; ≥ 32 MB, ≥ 4 cores, 2 workers, only parse of the batch, no scope):** `StreamAllMeshes`' order is read from the running web-ifc with a probe model (`_ccIfcStreamOrder`; the probe MUST be opened with a small `TAPE_SIZE` — OpenModel reserves 64 MB per model and the heap never shrinks), shards stream block-cyclic slices with `StreamMeshes`, `_ccMergeIfcShards` rebuilds one single-worker message and `_ccDecodeIfcWorkerResult` decodes it (same decoder as one worker). Any shard failure → one worker. Memory: one model copy per shard. Gates: `tests/ifc-shard-order.test.js`, `tests/browser/shard-load.mjs`, differential sharded case. Speed-up is real only with idle cores (see docs/PERFORMANCE_NOTES.md); worker/fallback agree on non-physical elements since 2026-10-23 (§21.49).
- **Federation memory (2026-10-23, flag `leanMemory`, default on; INTERNALS §21.46):** batched source geometry reads `position`/`normal` through VIEWS of the BatchedMesh's arrays (one CPU copy) — never transfer/detach a geometry array's `.buffer`, and copy (`.slice()`/`new Float32Array(a)`) before `postMessage`/IndexedDB: structured clone of a view serializes the WHOLE batch buffer. Never store a closure created inside `_detectClashesCore` anywhere long-lived (it pins the run's whole context). Gate: `tests/browser/memory-federation.mjs` (`MEM_FED_REF_ROOT=<old checkout>` compares against old code).
